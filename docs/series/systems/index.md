程序跑起来之后，它就和内核、和硬件发生了关系：地址空间是怎么映射的、系统调用花了多少时间、线程在哪里卡住、为什么这里会段错误。

这个系列关心的是**可观测性**：出了问题时，你有没有手段把它看见。

## 已发布

- [gdb 的第一小时](../../blog/posts/2026-10-13-gdb-first-hour.md)
  从「段错误，核心已转储」到定位到具体那一行，只需要十来个命令。

## 接下来写

- `fork` / `exec` / `wait`：一个 shell 到底做了什么
- ELF 与链接：目标文件里到底有什么，链接器在拼什么
- 虚拟内存与缺页：`malloc` 返回的地址为什么看起来那么大
- `strace` 和 `ltrace`：不用改代码就能看清程序在跟谁说话
- `perf`：采样、火焰图，以及「为什么这段代码不在热点里」
- 线程与锁：用 `helgrind` / TSan 抓数据竞争

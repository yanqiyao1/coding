## 在解决什么问题

预训练解决「模型知道什么」，后训练解决「模型会不会用、听不听话、稳不稳定」。

这个岗位的日常不是「调一个 loss」，而是：**发现能力短板 → 设计数据和方法 → 训练 → 评测 → 判断这次提升是真的还是幻觉**。所以它既需要算法（偏好学习、RL），也需要工程（数据管线、训练稳定性）和分析能力（实验设计）。

## 后训练包括什么

| 类型 | 做什么 | 典型方法 |
| --- | --- | --- |
| 指令微调 | 学会按指令回答、使用工具 | SFT、loss masking、数据配比 |
| 偏好学习 | 对齐人类偏好，学会取舍 | DPO、IPO、KTO、ORPO |
| 强化学习 | 在可验证任务上继续提升 | RLHF、RLVR、PPO、GRPO |
| 继续预训练 | 补领域知识、扩上下文 | 领域语料、位置插值、长文数据 |
| 多模态对齐 | 让模型看懂图/音/视频 | 投影层对齐、指令微调、偏好优化 |

## 四个能力维度

| 维度 | 具体能力 | 难点 |
| --- | --- | --- |
| **Reasoning / Math / Code** | 多步推理、数学证明、代码生成 | 奖励设计、难度课程、长度偏置 |
| **Agent / Tool Use / Planning** | 调用工具、多步规划、长程任务 | 稀疏奖励、环境构建、credit assignment |
| **Long Context** | 长文档理解、仓库级代码 | 位置外推、注意力效率、评测构造 |
| **多模态** | 图文理解、视频、语音 | 对齐阶段、数据质量、模态间干扰 |

## 方法栈

### SFT：数据质量 > 数据数量

- 指令-回答对，loss 只在回答上算（prompt 部分 mask 掉）
- 数据配比决定能力分布：数学、代码、通用对话的比例会直接反映在评测上
- 常见问题：格式单一、回答过长、模板泄漏

### 偏好学习

| 方法 | 思路 | 特点 |
| --- | --- | --- |
| **DPO** | 用偏好对直接优化策略，隐式奖励 | 稳定、便宜，但离线 |
| **IPO** | 换掉 DPO 的 pairwise 假设 | 抗过拟合偏好数据 |
| **KTO** | 只需要「好/坏」标签，不需要成对 | 数据更容易收集 |
| **ORPO** | 把 SFT 和偏好优化合成一步 | 省一次训练 |

### 强化学习

RLHF / RLVR / PPO / GRPO 的细节在[强化学习方向](../rl/index.md)，这里只记一句话：**后训练里 RL 的价值是把「能做对」变成「稳定做对」**，而不是教新知识。

### 数据：后训练的真正壁垒

| 手段 | 说明 |
| --- | --- |
| **合成数据** | 用强模型生成指令/回答，Self-Instruct 是最早的范式 |
| **拒绝采样** | 每个 prompt 采样多条，用 verifier 或 RM 筛出最好的 |
| **数据回流** | 线上 badcase → 标注/修正 → 回到训练集 |
| **自蒸馏** | 用模型自己的高质量输出训练自己（或蒸馏到小模型） |
| **Self-play** | 模型出题 + 解题，验证器筛选，形成难度课程 |

!!! note "合成数据的两个坑"

    一是**分布漂移**：合成数据往往比真实用户输入「干净」，训完在真实场景掉点。二是**自我强化**：用自己的输出训练自己，会把错误也一起放大——所以必须有一个独立的验证器或人工抽检。

### 奖励

- **RM**：学出来的打分器，适合「好不好」这类主观偏好
- **Verifier**：规则判断，适合数学答案、单测
- **PRM**：给每一步打分，用于过程监督和搜索

## 评测与实验分析

这部分最容易被忽略，但面试最看重。

**1. 选对 benchmark**

训练集和评测集必须隔离；注意 benchmark 污染（题目进了预训练语料）。常用：MMLU、GSM8K、MATH、HumanEval、MBPP、SWE-bench Verified、MT-Bench、Arena。

**2. 控制变量**

- 固定数据量、训练步数、算力预算
- 多跑几个 seed，报告方差而不是单次最好结果
- 输出长度、采样温度这些「隐性变量」也要固定

**3. 判断提升是不是真的**

- 换一个没参与调参的 benchmark
- 看 pass@1，不要只看 pass@k
- 检查是不是靠格式/长度/关键词蒙对
- 做消融：去掉数据的一类、换掉奖励的一项，看指标怎么动

**4. 分析错误**

把 badcase 分类（理解错、推理断、格式错、拒答），才知道下一步该补数据还是改方法。

## 学习路径

1. **基础**：Transformer、SFT 的实现细节、训练/推理的显存与并行
2. **偏好学习**：DPO 推导 → IPO/KTO/ORPO 的差异
3. **RL**：RLHF 三阶段 → RLVR/GRPO → 奖励设计
4. **数据**：合成、拒绝采样、回流、自蒸馏，各写一遍最小实现
5. **评测**：自己搭一套评测脚本，能算 pass@k、能跑消融

## 面试常问

**Q：SFT 和 RLHF 分别解决什么问题？**

SFT 教格式和基本能力，RLHF 优化「在多个合理回答里选更好的」。前者是模仿，后者是优化偏好。

**Q：DPO 的损失怎么来的？**

在 KL 正则下，最优策略有闭式解 `π* ∝ π_ref · exp(r/β)`，反解出 `r = β log(π*/π_ref)`，代回 Bradley-Terry 就得到只含策略和参考模型的损失。

**Q：什么时候用 DPO，什么时候用 PPO？**

数据固定、追求稳定和便宜 → DPO；需要 online 探索、奖励可验证（数学/代码）→ PPO/GRPO。

**Q：怎么判断数据质量？**

看多样性（聚类覆盖）、难度分布、长度分布、去重率、以及小模型上的可学习性（太难的样本学不动）。

**Q：长上下文怎么训？**

位置插值/外推（PI、YaRN）+ 长文数据（长文档 QA、仓库级代码）+ 评测要覆盖「中间位置」的信息，避免只测开头结尾。

**Q：多模态后训练的关键是什么？**

对齐阶段的数据质量（图文对是否真的对应）和指令微调阶段的任务多样性；常见问题是语言能力退化，需要混入纯文本数据。
